# 요구사항 문서 (Requirements Document)

## 소개

점심 메뉴 추천 앱은 사용자의 현재 날씨, 기분, 특정 이벤트, 가격대 등의 조건을 기반으로 주변 식당에서 점심 메뉴를 추천해주는 iOS 앱이다. GPS를 활용하여 사용자 주변 200미터 반경의 식당을 네이버 지도 API(Naver Map API)를 통해 검색하고, 조건에 맞는 식당 3곳을 추천한다. 또한 매일 지정된 시간에 로컬 알림(Local Notification)을 통해 점심 메뉴 추천을 받을 수 있다.

시스템은 클라이언트(iOS 앱) + 백엔드 서버(컨테이너 기반) 구조로 구성된다. 추천 엔진 로직과 네이버 지도 API 호출은 백엔드 서버에서 처리하며, iOS 앱은 사용자 인터페이스와 디바이스 기능(GPS, 알림)을 담당한다.

## 용어 사전 (Glossary)

- **앱(App)**: Swift/SwiftUI로 개발된 iOS 점심 메뉴 추천 클라이언트 애플리케이션
- **백엔드_서버(Backend_Server)**: 컨테이너(Docker) 기반으로 배포되는 서버 애플리케이션. 추천 엔진, 네이버 지도 API 호출 등 핵심 비즈니스 로직을 처리한다.
- **추천_엔진(Recommendation_Engine)**: 사용자 입력 조건(날씨, 기분, 이벤트, 가격대)을 기반으로 식당을 필터링하고 추천하는 백엔드 모듈
- **위치_서비스(Location_Service)**: iOS Core Location 프레임워크를 사용하여 사용자의 현재 GPS 좌표를 가져오는 클라이언트 모듈
- **식당_검색_서비스(Restaurant_Search_Service)**: 백엔드에서 네이버 지도 API를 통해 주변 식당 정보를 검색하는 모듈
- **알림_서비스(Notification_Service)**: iOS UNUserNotificationCenter를 사용하여 로컬 알림을 예약하고 발송하는 클라이언트 모듈
- **API_클라이언트(API_Client)**: iOS 앱에서 백엔드 서버와 REST API로 통신하는 모듈
- **추천_조건(Recommendation_Criteria)**: 날씨, 기분, 이벤트, 가격대로 구성된 사용자 입력 조건 집합
- **날씨(Weather)**: 현재 기상 상태 (맑음, 흐림, 비, 눈 등)
- **기분(Mood)**: 사용자가 선택한 현재 감정 상태 (기쁨, 보통, 우울, 피곤 등)
- **이벤트(Event)**: 특정 상황 또는 행사 (회식, 데이트, 혼밥, 다이어트 등)
- **가격대(Price_Range)**: 사용자가 설정한 식사 예산 범위 (저가, 중가, 고가)
- **추천_결과(Recommendation_Result)**: 추천_엔진이 생성한 식당 3곳의 목록
- **컨테이너(Container)**: Docker 기반의 격리된 실행 환경으로, 백엔드 서버를 패키징하고 배포하는 단위

## 요구사항

### 요구사항 1: 사용자 추천 조건 입력

**사용자 스토리:** 사용자로서, 날씨, 기분, 이벤트, 가격대를 입력하여 나에게 맞는 점심 메뉴를 추천받고 싶다.

#### 인수 조건 (Acceptance Criteria)

1. WHEN 사용자가 추천 화면을 열면, THE 앱 SHALL 날씨, 기분, 이벤트, 가격대 입력 폼을 표시한다.
2. THE 앱 SHALL 날씨 선택지로 맑음, 흐림, 비, 눈 4가지를 제공한다.
3. THE 앱 SHALL 기분 선택지로 기쁨, 보통, 우울, 피곤 4가지를 제공한다.
4. THE 앱 SHALL 이벤트 선택지로 회식, 데이트, 혼밥, 다이어트, 없음 5가지를 제공한다.
5. THE 앱 SHALL 가격대 선택지로 저가(1만원 미만), 중가(1만원~2만원), 고가(2만원 초과) 3가지를 제공한다.
6. WHEN 사용자가 모든 추천_조건을 선택하고 추천 버튼을 누르면, THE 앱 SHALL API_클라이언트를 통해 백엔드_서버에 추천 요청을 전송한다.
7. IF 사용자가 추천_조건 중 하나라도 선택하지 않으면, THEN THE 앱 SHALL 미선택 항목을 강조 표시하고 선택을 요청하는 안내 메시지를 표시한다.

### 요구사항 2: GPS 기반 주변 식당 검색

**사용자 스토리:** 사용자로서, 내 현재 위치 주변의 식당을 자동으로 검색하여 가까운 곳에서 식사할 수 있도록 하고 싶다.

#### 인수 조건 (Acceptance Criteria)

1. WHEN 사용자가 추천을 요청하면, THE 위치_서비스 SHALL 사용자의 현재 GPS 좌표를 가져온다.
2. WHEN GPS 좌표를 획득하면, THE 앱 SHALL 좌표와 추천_조건을 백엔드_서버에 전송하고, THE 백엔드_서버 SHALL 네이버 지도 API를 호출하여 반경 200미터 이내의 식당 목록을 가져온다.
3. IF 위치 권한이 허용되지 않은 상태이면, THEN THE 앱 SHALL 위치 권한 요청 다이얼로그를 표시한다.
4. IF 위치 권한 요청이 거부되면, THEN THE 앱 SHALL "위치 권한이 필요합니다. 설정에서 권한을 허용해주세요."라는 안내 메시지를 표시한다.
5. IF 백엔드_서버 또는 네이버 지도 API 호출이 실패하면, THEN THE 앱 SHALL "식당 검색에 실패했습니다. 네트워크 연결을 확인해주세요."라는 오류 메시지를 표시한다.
6. IF 반경 200미터 이내에 식당이 없으면, THEN THE 앱 SHALL "주변에 검색된 식당이 없습니다."라는 안내 메시지를 표시한다.

### 요구사항 3: 점심 메뉴 추천

**사용자 스토리:** 사용자로서, 내 조건에 맞는 식당 3곳을 추천받아 빠르게 점심 메뉴를 결정하고 싶다.

#### 인수 조건 (Acceptance Criteria)

1. WHEN 백엔드_서버가 식당 목록을 확보하면, THE 추천_엔진 SHALL 추천_조건에 따라 식당을 필터링하고 점수를 매긴다.
2. THE 추천_엔진 SHALL 점수가 높은 순서대로 상위 3개 식당을 추천_결과로 반환한다.
3. THE 앱 SHALL 추천_결과에 각 식당의 이름, 카테고리, 거리, 가격대 정보를 표시한다.
4. IF 추천_조건에 맞는 식당이 3곳 미만이면, THEN THE 추천_엔진 SHALL 조건에 맞는 식당만 추천_결과로 반환한다.
5. IF 추천_조건에 맞는 식당이 0곳이면, THEN THE 앱 SHALL "조건에 맞는 식당이 없습니다. 조건을 변경해보세요."라는 안내 메시지를 표시한다.
6. WHEN 추천_결과가 표시된 상태에서 사용자가 다시 추천 버튼을 누르면, THE 추천_엔진 SHALL 이전 추천과 다른 식당을 우선적으로 추천한다.

### 요구사항 4: 로컬 알림을 통한 점심 추천

**사용자 스토리:** 사용자로서, 매일 지정된 시간에 점심 메뉴 추천 알림을 받아 앱을 열지 않아도 추천을 확인하고 싶다.

#### 인수 조건 (Acceptance Criteria)

1. THE 앱 SHALL 알림 시간을 설정할 수 있는 설정 화면을 제공한다.
2. WHEN 사용자가 알림 시간을 설정하면, THE 알림_서비스 SHALL 해당 시간에 매일 반복되는 로컬 알림을 예약한다.
3. WHEN 예약된 알림 시간이 되면, THE 알림_서비스 SHALL "점심 뭐 먹지? 지금 추천받아 보세요!"라는 알림을 발송한다.
4. WHEN 사용자가 알림을 탭하면, THE 앱 SHALL 추천 조건 입력 화면으로 이동한다.
5. IF 알림 권한이 허용되지 않은 상태이면, THEN THE 앱 SHALL 알림 권한 요청 다이얼로그를 표시한다.
6. IF 알림 권한 요청이 거부되면, THEN THE 앱 SHALL "알림 권한이 필요합니다. 설정에서 권한을 허용해주세요."라는 안내 메시지를 표시한다.
7. WHEN 사용자가 알림을 비활성화하면, THE 알림_서비스 SHALL 예약된 모든 알림을 취소한다.

### 요구사항 5: 추천 결과 표시

**사용자 스토리:** 사용자로서, 추천된 식당의 상세 정보를 확인하여 식당을 선택하고 싶다.

#### 인수 조건 (Acceptance Criteria)

1. WHEN 추천_결과가 생성되면, THE 앱 SHALL 추천된 식당 3곳을 카드 형태로 표시한다.
2. THE 앱 SHALL 각 식당 카드에 식당 이름, 음식 카테고리, 현재 위치로부터의 거리(미터 단위), 가격대를 표시한다.
3. WHEN 사용자가 식당 카드를 탭하면, THE 앱 SHALL 네이버 지도 앱 또는 웹 브라우저로 해당 식당의 위치를 연다.
4. IF 네이버 지도 앱이 설치되어 있지 않으면, THEN THE 앱 SHALL 사파리(Safari) 브라우저를 통해 네이버 지도 웹 페이지로 해당 식당 위치를 연다.

### 요구사항 6: 앱 초기 실행 및 권한 관리

**사용자 스토리:** 사용자로서, 앱을 처음 실행할 때 필요한 권한을 안내받아 원활하게 앱을 사용하고 싶다.

#### 인수 조건 (Acceptance Criteria)

1. WHEN 앱이 최초 실행되면, THE 앱 SHALL 위치 서비스 권한을 요청한다.
2. WHEN 위치 권한 요청이 완료되면, THE 앱 SHALL 알림 권한을 요청한다.
3. THE 앱 SHALL 각 권한 요청 전에 해당 권한이 필요한 이유를 설명하는 안내 화면을 표시한다.
4. WHILE 앱이 실행 중인 상태에서, THE 위치_서비스 SHALL "앱 사용 중에만(While Using the App)" 위치 접근 권한을 사용한다.
5. IF 필수 권한(위치)이 거부된 상태이면, THEN THE 앱 SHALL 메인 화면에 권한 설정 안내 배너를 표시한다.

### 요구사항 7: 클라우드 네이티브 백엔드 아키텍처

**사용자 스토리:** 개발자로서, 백엔드 서버를 컨테이너 기반으로 구성하여 확장성과 배포 편의성을 확보하고 싶다.

#### 인수 조건 (Acceptance Criteria)

1. THE 백엔드_서버 SHALL Docker 컨테이너로 패키징되어 배포 가능해야 한다.
2. THE 백엔드_서버 SHALL REST API를 통해 iOS 앱과 통신한다.
3. WHEN iOS 앱이 추천 요청을 보내면, THE 백엔드_서버 SHALL GPS 좌표와 추천_조건을 수신하고, 네이버 지도 API 호출 및 추천 엔진 실행을 처리하여 추천_결과를 반환한다.
4. THE 백엔드_서버 SHALL 네이버 지도 API 키를 환경 변수로 관리하여 클라이언트에 노출하지 않는다.
5. THE 백엔드_서버 SHALL 헬스체크(health check) 엔드포인트를 제공하여 컨테이너 오케스트레이션 도구가 서버 상태를 모니터링할 수 있도록 한다.
6. IF 백엔드_서버가 응답하지 않으면, THEN THE 앱 SHALL "서버에 연결할 수 없습니다. 잠시 후 다시 시도해주세요."라는 오류 메시지를 표시한다.
7. THE 백엔드_서버 SHALL 요청/응답 로깅을 통해 디버깅 및 모니터링을 지원한다.
